# PRAVDA

PRAVDA — большой документальный сайт со статьями об истории, праве и политическом контексте российско-украинской войны.

Один корпус статей доступен в трёх представлениях:

- **Хроно** — те же статьи на временной шкале;
- **Связи** — те же статьи как граф смысловых и хронологических переходов;
- **Статьи** — пронумерованный, сортируемый каталог всего корпуса.

Отдельно работает frontend-прототип AI-помощника: он распознаёт тему разговора и
ведёт к релевантным статьям, но не создаёт ещё одну публичную сущность контента.

## Что уже работает

### Хроно

- перетаскивание шкалы мышью и пальцем;
- инерционное движение;
- `Cmd/Ctrl + колесо` для масштабирования вокруг курсора;
- даты над осью, статьи под осью;
- компактные группы статей с одинаковой датой;
- переход из каждой точки в полный текст статьи;
- RU / EN / UA и светлая / тёмная темы.

### Связи

- граф на `@xyflow/react`;
- выбранный узел всегда находится в центре;
- входящие связи расположены слева, исходящие — справа;
- режимы глубины в один и два шага;
- поиск по статьям;
- инспектор статьи с кратким пояснением переходов;
- каждый узел карты открывает тот же материал, что Хроно и каталог.

Во всех трёх представлениях используется одно и то же множество статей с одинаковыми идентификаторами, номерами и ссылками. События, понятия и аргументы описываются внутри статьи, но не существуют как отдельные публичные сущности.

### Статьи

- 85 полноценных статей в едином корпусе;
- единый поиск, сортировка по номеру и названию, постраничная навигация;
- хронологическая нумерация едина для каталога, Хроно и Связей: вставка более раннего материала автоматически пересчитывает все последующие номера, не меняя стабильные URL;
- каждый материал развёрнут в контекстные разделы, а тезисы, события и возможные возражения объясняются внутри единого повествования;
- внутри текста размещены ссылки на официальные документы и институциональные источники;
- исследовательские транскрипты не показываются читателю и не используются как публичное доказательство;
- переходы между соседними статьями и открытие любого материала в графе.

### AI

- обязательное подтверждение уведомления участников разговора;
- запуск и остановка браузерного распознавания речи, если доступен Web Speech API;
- ручное редактирование или вставка текста разговора;
- демонстрационный разговор без микрофона;
- локальное обнаружение тем по ключевым словам;
- динамическая карта темы и связанных документов;
- три ответа: уточняющий вопрос, документальная формулировка и граница допустимого вывода;
- копирование ответа;
- переход к связанным статьям и карте.

Текущий AI — **не production-ИИ**. Он не вызывает LLM и не отправляет аудио на backend. Полная потоковая архитектура описана в [`docs/PLAN.md`](docs/PLAN.md) и [`docs/AI_REALTIME_PROTOCOL.md`](docs/AI_REALTIME_PROTOCOL.md).

## Стек

- React 19 + TypeScript;
- Vite;
- React Router с `BrowserRouter` и `404.html`-возвратом маршрута для GitHub Pages;
- React Flow (`@xyflow/react`) для графа;
- Zustand с persist middleware для темы, языка и выбранного узла;
- Vitest и ESLint; включены unit-тесты распознавания тем, графового layout и целостности единого корпуса статей и связей.

## Запуск

Требуется Node.js 22.12+ (либо совместимая ветка Node 20.19+).

```bash
npm install
npm run dev
```

Production-сборка:

```bash
npm run build
npm run preview
```

Проверка ссылочной целостности данных:

```bash
npm run generate:data
npm run verify:data
```

`generate:data` запускает внутренний Node-side builder и записывает чистый публичный
реестр. Приложение не импортирует файлы с исследовательскими транскриптами; сборка
дополнительно проверяется командой `verify:dist`.

## GitHub Pages

Workflow уже находится в `.github/workflows/pages.yml`.

1. Создайте репозиторий и отправьте ветку `main`.
2. В GitHub откройте `Settings → Pages`.
3. В `Source` выберите **GitHub Actions**.
4. Следующий push соберёт и опубликует `dist`.

### Стандартное правило деплоя для этого проекта

В этом репозитории действует правило: после любого изменения кода или контента изменения нужно сразу **фиксировать и пушить** в `main`.

Порядок:

1. Внести изменения.
2. Выполнить `npm run generate:data`.
3. Последовательно запустить `npm run verify:data`, `npm test`,
   `npm run typecheck`, `npm run lint`, `npm run build`.
4. Выполнить `git add <files>`, `git commit -m "..."` и `git push`.
5. GitHub Actions повторит проверки и опубликует сборку в GitHub Pages.

Т.е. не нужно ждать отдельного запроса “сделай деплой” — по умолчанию каждый push в `main` идёт в deploy-пайплайн.

### Внутренний исследовательский конвейер

Актуальный конвейер полностью локальный: оригинальное YouTube-аудио, полный
`faster-whisper large-v3` с фиксированным русским языком и локальная идентификация
голоса через WeSpeaker ECAPA. `youtube-transcript.ai` больше не является
основным источником из-за дублирования реплик и низкого качества текста.

Транскрипты помогают редакции увидеть темы и выстроить нарратив. Они не являются
публичным первичным источником, не цитируются на сайте и не связывают автора видео
с проектом. Исторические и правовые утверждения проверяются по официальным
документам и институциональным публикациям.

Полные команды, структура хранения, текущая точка продолжения, правила голосового
банка и порядок ручной докалибровки находятся в
[`docs/TRANSCRIPTION_PIPELINE.md`](docs/TRANSCRIPTION_PIPELINE.md).

Канонические результаты хранятся как
`transcripts/vzglyad-iz-chetvertogo-izmereniya/<VIDEO_ID>.md`. Техническое аудио,
JSONL и голосовые эмбеддинги остаются только в `.local/`.

Для создания репозитория через GitHub CLI:

```bash
./scripts/publish-github.sh pravda private
```

## Ограничения браузерного аудио

Обычная веб-страница не может скрытно слушать системный звук или вкладку чат-рулетки. Текущий прототип работает только с разрешённым микрофоном и поддерживаемым браузером. Для полноценного диалога нужны:

- явное согласие участников;
- `getDisplayMedia` для добровольного захвата аудио вкладки либо расширение браузера;
- потоковый STT на backend;
- диаризация или другой способ различать собеседников;
- политика хранения и удаления записей.

## Принципы качества

PRAVDA должна отделять:

1. текст первичного документа;
2. установленный факт;
3. историческую причинную гипотезу;
4. политическую или моральную оценку;
5. риторический приём.

Связи помогают переходить между статьями, но сами по себе не доказывают причинность. Ответы AI должны вести к источникам, показывать границу вывода и не выдавать спорную причинность за установленный факт.
