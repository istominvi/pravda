# Локальный конвейер транскрибации канала Александра

Этот документ является основным источником истины для продолжения транскрибации
роликов канала «Взгляд из Четвертого Измерения».

Если пользователь в новой сессии говорит «продолжай со следующего ролика» или просит
обработать несколько следующих роликов, Codex должен самостоятельно пройти весь
конвейер ниже: определить нужные `VIDEO_ID`, скачать оригинальное аудио, выполнить
полную расшифровку, выделить Александра, сохранить итоговые Markdown-файлы,
выполнить полный локальный pipeline, закоммитить и запушить результат. Повторная
ручная разметка по умолчанию не нужна.

## 1. Цель и границы задачи

- Нужны точные русскоязычные реплики Александра как внутренний исследовательский
  материал для восстановления смыслового нарратива и поиска вопросов, которые
  следует раскрыть или уточнить в статьях.
- Александр не имеет отношения к проекту PRAVDA. Его имя, видео, `VIDEO_ID`,
  таймкоды и транскрипты не используются в публичной атрибуции, тексте или списке
  источников статьи.
- Канал построен на чат-рулетке. Собеседники постоянно меняются, поэтому их личности
  не определяются и не переносятся между роликами.
- Классы голоса только три: `Александр`, `Другой голос`, `Не уверен`.
- Перебивания и одновременная речь могут быть смешаны в одном ASR-сегменте. Такой
  сегмент нельзя считать чистым отрицательным примером голоса Александра.
- Текст и идентификация голоса являются разными этапами: Whisper распознает слова,
  WeSpeaker/ECAPA сравнивает голос с локальным голосовым банком.

## 3. Где хранятся данные

### Канонический результат, который коммитится

```text
transcripts/vzglyad-iz-chetvertogo-izmereniya/<VIDEO_ID>.md
```

Имя файла всегда равно YouTube `VIDEO_ID`. Внутри находятся таймкоды, текст и одна
из трех подписей голоса. Этот Markdown нужен только для внутреннего редакционного
анализа нарратива; приложение не импортирует его и не показывает как публичный
источник.

### Локальные технические данные, которые не коммитятся

```text
.local/youtube-audio-original/<VIDEO_ID>.webm
.local/transcription-cache/vzglyad-iz-chetvertogo-izmereniya/<VIDEO_ID>/
.local/alexander-voicebank/
.local/speaker-labeling/<VIDEO_ID>/
.local/voice-tools-venv/
```

`.local/` содержит оригинальное аудио, JSONL с временными метками слов, технический
speaker JSONL, ONNX-модель, голосовые эмбеддинги и ручную разметку. Это локальные,
в том числе биометрические, данные. Их нельзя коммитить или отправлять во внешние
сервисы.

`transcripts/raw-youtube/` не изменять и не использовать как основу. Это резервный
низкокачественный материал от старого конвейера. В нем встречались двойные реплики,
ошибочная пунктуация и потеря смысла.

## 4. Рабочий стек

### Распознавание слов

- `scripts/transcribe-multilingual.py`
- локальный `faster-whisper`
- полная модель `large-v3`, не `tiny`, `base`, `turbo` или сокращенный вариант
- CPU `int8`, beam search 8, patience 1.2
- VAD и временные метки отдельных слов
- оригинальное YouTube Opus/WebM без промежуточного повторного сжатия
- по умолчанию фиксированный `language="ru"`

Фиксированный русский выбран намеренно. Александр говорит по-русски, а внутреннему
редакционному процессу нужны прежде всего его смысловые линии. Редкие украинские
реплики собеседников могут быть распознаны хуже, но они все равно помечаются как
`Другой голос`. Флаг
`--multilingual` применять только тогда, когда сам Александр значительную часть
ролика говорит по-украински или пользователь просит точно сохранить речь гостей.

### Идентификация Александра

- `scripts/alexander-voiceprint.py`
- локальная WeSpeaker ECAPA-TDNN512 ONNX
- постоянный голосовой банк: `.local/alexander-voicebank/`
- текущее подтвержденное состояние: 108 примеров Александра и 20 чистых
  обезличенных отрицательных примеров
- последний leave-one-out контроль банка: 121 правильно, 3 неопределенных,
  0 ложных `Александр`, 4 пропуска Александра, всего 128

Банк по умолчанию заморожен. При обработке нового ролика программа может временно
добавить до 32 очень уверенных `episodeSeeds` только внутри этого ролика. Эти
векторы не записываются в постоянный банк.

## 5. Полный автоматический проход одного ролика

Команды ниже выполнять из корня репозитория.

### Шаг 1. Задать идентификатор и пути

```bash
VIDEO='<VIDEO_ID>'
CHANNEL='vzglyad-iz-chetvertogo-izmereniya'
AUDIO=".local/youtube-audio-original/$VIDEO.webm"
CACHE=".local/transcription-cache/$CHANNEL/$VIDEO"
```

### Шаг 2. Скачать лучшее оригинальное аудио

```bash
mkdir -p .local/youtube-audio-original
yt-dlp --no-playlist \
  -f 'bestaudio[ext=webm]/bestaudio/best' \
  -o "$AUDIO" \
  "https://youtu.be/$VIDEO"
```

Не извлекать WAV/MP3 заранее и не перекодировать аудио. Скрипты сами декодируют
исходный контейнер через `ffmpeg`.

### Шаг 3. Запустить полную русскую `large-v3`

```bash
python3 scripts/transcribe-multilingual.py \
  --video-id "$VIDEO" \
  --extra-hotwords '<имена, географические названия и термины из заголовка>'
```

`--extra-hotwords` должен содержать только несколько вероятных имен и терминов.
Нельзя превращать его в пересказ ожидаемого содержания: это может искусственно
исказить текст.

Для обычного ролика на CPU обработка может идти 15-40 минут. На перебиваниях
индикатор прогресса способен долго стоять или показывать неравномерную скорость.
Это не повод запускать второй процесс. Нужно продолжать ждать тот же процесс до
итогового JSON с `segments`, `duration`, `initialLanguage` и `output`.

Если нужен полноценный RU/UA режим:

```bash
python3 scripts/transcribe-multilingual.py \
  --video-id "$VIDEO" \
  --multilingual \
  --extra-hotwords '<краткий список терминов>'
```

### Шаг 4. Выделить Александра без обучения банка

```bash
PY='.local/voice-tools-venv/bin/python'

"$PY" scripts/alexander-voiceprint.py identify \
  --audio "$AUDIO" \
  --transcript "$CACHE/$VIDEO.jsonl" \
  --output-jsonl "$CACHE/$VIDEO.speaker-identified.jsonl" \
  --output-markdown "$CACHE/$VIDEO.speaker-identified.md"
```

Ожидаемый итог команды:

```json
{"alexander": 91, "other": 34, "uncertain": 2, "episodeSeeds": 32}
```

Числа будут разными для каждого ролика. Наличие `episodeSeeds` не означает
переобучение постоянного банка.

### Шаг 5. Положить только канонический Markdown

```bash
mkdir -p "transcripts/$CHANNEL"
cp -- "$CACHE/$VIDEO.speaker-identified.md" \
  "transcripts/$CHANNEL/$VIDEO.md"
```

Не копировать в `transcripts/` сырой JSONL, TXT, VTT, аудио, клипы разметки или
альтернативные версии `tiny/base/turbo`.

### Шаг 6. Зафиксировать результат

Для одного ролика:

```bash
npm run generate:data
npm run verify:data
npm test
npm run typecheck
npm run lint
npm run build
git add -- "transcripts/$CHANNEL/$VIDEO.md"
git commit -m "Add canonical transcript for $VIDEO"
git push origin main
```

Если пользователь запросил сразу несколько роликов, конвейер можно последовательно
пройти для всех и сделать один связный коммит в конце. Не останавливаться после
каждого ролика для подтверждения, если пользователь заранее задал весь диапазон.

### Шаг 7. Короткий отчет пользователю

Сообщить:

- какие `VIDEO_ID` готовы;
- длительность и количество ASR-сегментов каждого ролика;
- распределение `Александр / Другой голос / Не уверен`;
- абсолютные ссылки на канонические `.md`;
- commit hash и факт push;
- что постоянный голосовой банк не изменялся.

## 6. Когда ручная разметка не нужна

Не просить пользователя снова размечать голоса только потому, что началась новая
сессия или новый ролик. Текущий банк уже покрывает новые и старые записи, разные
микрофоны и несколько эпох канала.

Продолжать полностью автоматически, если:

- большинство очевидных реплик Александра помечаются правильно;
- нет серии очевидных ложных `Александр`;
- в ролике получены уверенные `episodeSeeds`;
- сомнительные смешанные фрагменты остаются в `Не уверен` или единичны.

Ручная докалибровка оправдана только при реальном сдвиге качества: новая эпоха
записи/микрофон, почти полное отсутствие `episodeSeeds`, систематические пропуски
Александра или массовые ложные совпадения с гостем.

## 7. Безопасная ручная докалибровка при необходимости

### Подготовить локальную страницу

```bash
VIDEO='<VIDEO_ID>'
CHANNEL='vzglyad-iz-chetvertogo-izmereniya'
AUDIO=".local/youtube-audio-original/$VIDEO.webm"
CACHE=".local/transcription-cache/$CHANNEL/$VIDEO"
REVIEW=".local/speaker-labeling/$VIDEO"

python3 scripts/speaker-labeler.py build \
  --audio "$AUDIO" \
  --transcript "$CACHE/$VIDEO.jsonl" \
  --root "$REVIEW" \
  --video-id "$VIDEO" \
  --count 60

python3 scripts/speaker-labeler.py serve \
  --root "$REVIEW" \
  --port 8766
```

Открыть `http://127.0.0.1:8766/?review=<VIDEO_ID>`. Если порт занят, выбрать другой
свободный порт. Если браузер показывает `Directory listing`, сервер запущен не из
той review-папки либо `index.html` еще не создан: снова выполнить `build`, затем
`serve --root "$REVIEW"`.

### Добавить только подтвержденного Александра

После разметки:

```bash
.local/voice-tools-venv/bin/python scripts/alexander-voiceprint.py build \
  --labels-root "$REVIEW" \
  --positive-only
```

Правило `--positive-only` обязательно для старых, шумных и перебиваемых роликов.
Человеческая метка `Собеседник` означает только «этот фрагмент не подходит как
чистый Александр». Она не доказывает, что в аудио совсем нет голоса Александра.
Поэтому такие фрагменты не добавляются как отрицательные эталоны.

`Несколько голосов` и `Не уверен` никогда не добавлять в голосовой банк.

Если отрицательные фрагменты шумного ролика были добавлены по ошибке:

```bash
.local/voice-tools-venv/bin/python scripts/alexander-voiceprint.py build \
  --skip-default-labels \
  --drop-negative-source '<VIDEO_ID>'
```

После изменения банка повторно выполнить только идентификацию затронутого ролика и
перезаписать его канонический Markdown.

## 8. Известные ошибки и чему научились

### Все реплики были подписаны «Александр»

Причина: имя ведущего было механически проставлено на ASR-сегменты без настоящего
сравнения голосовых эмбеддингов. Исправление: всегда запускать отдельный этап
`alexander-voiceprint.py identify`.

### Реплики дублировались дважды

Причина: старый источник `youtube-transcript.ai` возвращал перекрывающиеся или
повторяющиеся блоки. Исправление: он не является основным источником; использовать
оригинальное аудио и локальный `large-v3`.

### Текст был почти непригоден для чтения

Причина: маленькие/ускоренные Whisper-модели, повторное сжатие аудио и неверное
автоматическое переключение языка. Исправление: полный `large-v3`, оригинальный
WebM/Opus и фиксированный русский язык.

### Шумная разметка ухудшала голосовой банк

Причина: перебиваемый фрагмент, отмеченный как `Собеседник`, использовался как
жесткий отрицательный пример, хотя в нем мог звучать Александр. Исправление:
`--positive-only`; лучше показать модели чистого Александра, чем учить ее на
сомнительном «не Александр».

### Разные собеседники ошибочно воспринимались как постоянные личности

Причина: классическая диаризация разделяет голоса внутри конкретной записи, но
`Speaker A` из одного ролика не равен `Speaker A` из другого. Исправление: постоянна
только личность Александра; все остальные остаются анонимным классом.

### ONNX пишет предупреждение о telemetry device ID

Сообщение `Failed to persist telemetry device ID; using an in-memory identifier`
безопасно и не влияет на идентификацию.

### Прогресс Whisper закончился не на 100%, но появился итоговый JSON

Индикатор основан на обработанных временных окнах и иногда выглядит неточно после
VAD. Итоговый JSON с нулевым exit code и созданные JSONL-файлы означают успешное
завершение; не запускать расшифровку повторно только из-за процента индикатора.

## 9. Разделение транскрибации и публикации статей

Транскрибация сначала создаёт внутренний канонический корпус. Извлечение смысловых
линий выполняется отдельной редакционной задачей и опирается только на реплики,
помеченные `Александр`; `Не уверен` проверяется по аудио перед содержательным
использованием. Во внутренней памяти обязательно сохранять `VIDEO_ID` и таймкод,
отличать прямую формулировку от пересказа встречной позиции и не превращать
полемическую реплику в самостоятельный тезис без контекста.

После этого исходный материал перестаёт быть источником публичной статьи и служит
только ориентиром для её нарратива. Для каждого фактического и правового утверждения
нужно найти официальный первичный источник: текст закона, договора, решения,
резолюции или сообщение компетентного государственного/международного органа.
YouTube, канонический Markdown, GitHub-копия транскрипта и имя Александра не должны
попадать в публичные `sections`, `sources`, подписи или метаданные.

Публичная интеграция выполняется так:

1. Определить, какая из существующих 85 статей уже раскрывает вопрос. Дополнить её,
   если новая линия не меняет предмет материала.
2. Если нужна новая статья, развернуть её как самостоятельный документальный
   материал: задать `chronologyDate`, содержательный вводный текст, четыре раздела
   минимум по два абзаца и не менее 400 слов в каждой языковой версии, официальные
   HTTPS-источники и связи с другими статьями.
3. Не создавать публичные сущности «событие», «понятие» или «аргумент»: единственный
   публичный контракт — `ArticleRecord`. Редакционный builder находится в
   `src/data/articleBuilder.ts`, а браузер читает только чистую сгенерированную
   проекцию `src/data/articles.public.ts` через `src/data/articles.ts`.
4. Хроно, Связи и Статьи должны использовать один и тот же `articlesData`; различается
   только способ отображения — шкала времени, граф стрелок или пронумерованный список.
5. AI-тему связывать с корпусом только массивом `articleIds`; не возвращать отдельные
   `nodeIds`, `sourceEventIds` или `argumentIds`.
6. После редакционных правок выполнить `npm run generate:data`, затем
   `verify:data` → `test` → `typecheck` → `lint` → `build`, после чего один
   `git add` → `git commit` → `git push` в `main`.
