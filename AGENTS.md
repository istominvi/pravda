# AGENTS для PRAVDA

## Поведенческие правила для последующей работы в этом репозитории

- Любые изменения в коде/данных/контенте фиксируем как минимум одним commit в `main` и пушим в репозиторий.
- GitHub Pages деплоится автоматически по `push` в `main` через `.github/workflows/pages.yml`; отдельный ручной запрос на деплой не требуется.
- Перед публикацией изменения проходят pipeline: `verify:data` → `test` → `lint` → `build` → deploy.

## Операционный стандарт для новых сессий (чтобы не повторять ошибки)

1. Перед работой с проектом посмотреть:
   - `README.md` (структура и текущий статус)
   - `docs/CODEX_HANDOFF.md` (что уже в работе)
   - этот `AGENTS.md` (обязательные правила для сессии)

2. При работе с видео в порядке приоритета фиксировать:
   1. `VIDEO_ID` и сырой источник транскрипта.
   2. Ключевые тезисы и контраргументы с таймкодами.
   3. Где именно в проекте это уже есть (чтобы только дополнять, а не дублировать).
   4. Что новая логика подтверждает/уточняет/ограничивает в существующих темах.

3. После изменений всегда выполнять «один проход»:
   - обновить `src/data/aiKnowledge.ts` (и по необходимости `src/data/knowledge.ts`, `src/views/AIAssistantView.tsx`),
   - `git add ...`
   - `git commit`
   - `git push`

4. Не оставлять для следующей сессии неопределённости:
   - если есть изменения по видео/аргументам — сразу указывать их в памяти в формате шагов выше,
   - если не удалось завершить пайплайн, всё равно зафиксировать прогресс и точку остановки в handoff-доках.

## Стандартный порядок фиксации изменений после редактирования по видео

- Принять `VIDEO_ID` и сохранить сырые файлы транскриптов (json/vtt), чтобы потом можно было перепроверить смысл.
- Обновлять только релевантные фрагменты: темы AI/концепты/связи и тексты для демонстрации.
- После правок делаться одна связная commit-сообщение, отражающее видео-источник и суть дополнений.
- Push в `main` = триггер автодеплоя; отдельный ручной деплой не планировать, пока нет специальной инструкции.
- Если видео-анализ повторяется в будущих сессиях, использовать тот же шаблон и не придумывать новый порядок.

## Процедура анализа видео и транскрипций

- `transcripts/raw-youtube/` не изменяем: это резервный низкокачественный источник, а не основа анализа.
- Основную расшифровку делаем локально через `faster-whisper` с моделью `large-v3-turbo`, сохраняем `VIDEO_ID`, JSONL с пословными таймкодами, TXT и метаданные модели.
- `youtube-transcript.ai` допустим только как резерв для сверки; автоматически удаляем его дублирующиеся реплики и не подменяем им локальный транскрипт.
- Голоса размечаем как бинарную задачу: `Александр`, `Другой голос`, `Не уверен`. Личности меняющихся собеседников из чат-рулетки не устанавливаем.
- Локальный голосовой банк Александра строим и постепенно пополняем только по подтвержденным человеком фрагментам через `scripts/alexander-voiceprint.py`. ONNX-модель, аудиоклипы и биометрические векторы храним только в `.local/` и не коммитим.
- Сомнительные или смешанные фрагменты не приписываем Александру. Отрицательные примеры храним обезличенно и используем только для снижения ложных совпадений.
- Извлекаем тезисы и оппозиционные контраргументы без подмены смысла.
- Обновляем проект по месту в следующем порядке:
  1. `src/data/aiKnowledge.ts` — AI-топики/подсказки;
  2. `src/data/knowledge.ts` — концепты и связи;
  3. `src/views/AIAssistantView.tsx` — демонстрационный текст, если нужно.
- После изменений делаем `git add`, `git commit`, `git push`.

## Что считать обязательным к сохранению в памяти проекта

- Эта инструкция — рабочий ориентир для автоматизации, поэтому обновлять при смене пайплайна или методики обработки видео.
- Сначала проверять `README.md` и `docs/CODEX_HANDOFF.md` при handoff между сессиями.
